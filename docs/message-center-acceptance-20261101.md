## 交付功能

| 区域 | 实际行为 |
| --- | --- |
| 发布消息 | 富文本直写或模板填充、私有图片与附件、草稿保存/继续编辑、内容预览、重要程度、置顶、显式确认、有效期、内部业务入口、立即/定时发布 |
| 接收范围 | 用户、部门及下级、角色、岗位、全体用户的并集，最后应用排除人员；后端校验 RBAC 数据范围与有效账号，预览实际人数，发布固定接收名单及姓名/部门快照 |
| 发布记录 | SQL 筛选及分页、合并统计、详情、分页回执、按筛选导出 CSV、取消定时/排队、撤回、失败重试、复制为新消息、继续编辑/删除草稿 |
| 个人消息 | 全部/未读/重要/已归档文件夹、分类与时间查询、首次阅读、显式知悉、批量已读、归档和恢复、私有附件下载 |
| 顶部提醒 | 最近五条未读、未读数、全部已读、直达详情，复用布局中的唯一 WebSocket 连接；打开的详情收到撤回提醒或到期后重新核验状态 |
| 模板与配置 | 富文本模板 CRUD、启停、变量识别和真实服务端预览；消息分组配置、字典、独立动作权限、专用导航目录 |

模板和内容为真实数据库记录，不使用前端模拟数据。发送对象的预览、所有查询过滤、权限、收件归属和状态转换均在服务端再次校验。

## 实现约束

- `message_task` 存一份正文和发布规则；`message_recipient` 保存不可变接收人快照与投递回执；`message_attachment` 保存附件关联及文件元数据。个人记录关联发布任务，避免大正文按收件人数重复保存。
- 草稿使用客户端唯一请求键和乐观版本；发布需提交刚预览的版本和人员指纹。内容或人员改变必须重新预览，不能以过期人数确认发布。
- 调度默认每 1.5 秒处理最多 20 个任务，每任务每批 500 人。任务行锁保护多实例投递与人工状态操作，唯一键保证每任务每人最多一条收件记录。
- 批次写入与投递状态同事务提交；失败整批回滚，最多自动尝试三次，之后明确记录失败。人工重试仅处理失败人员，已成功人员不重复投递。通知采用持久化标记，Redis 连接恢复后继续提醒，允许重复提醒但不重复写收件记录。
- 取消只允许未开始投递的排队/定时任务，投递已开始后使用撤回。撤回保留回执，接收人无法继续读取正文、图片或附件；账号停用/删除和消息过期会跳过尚未投递人员。
- 已读与确认分开，首次时间不被重复操作覆盖；重复读取已读详情不重复发出状态通知，避免实时刷新循环。归档仅影响本人收件箱，不删除发布历史。
- 后端 JSoup、前端 DOMPurify 净化正文；变量作为文本转义，不执行表达式。正文图片只保留 `data-file-id`，图片地址由鉴权下载后生成。文件引用校验阻止删除有效消息正在使用的文件。
- 时间响应为 `yyyy-MM-dd HH:mm:ss`，定时和有效期固定日期时间选择，创建时间固定日期时间范围。SQL 和请求日志使用现有追踪号，开发 JDBC SQL 日志只输出语句结构，不输出正文和人员参数。

## 权限与默认配置

沿用 `message:send`、`message:query`、模板查询/维护权限，并增加全体发送、定时、全部记录查询、回执查询/导出、取消、撤回、失败重试和模板删除的独立权限。超级管理员使用现有通配权限；原有普通角色授权保持不变，由管理员按职责分配新增权限。

添加附件需 `file:upload`。接收人下载只要求命中消息授权关系，无需文件管理权限。旧 `/send` 调用也执行接收人数据范围校验，不能绕过新界面的权限限制。

系统配置「消息中心」的默认值：单条 20,000 人、定时范围 90 天、附件最多 10 个、撤回时限 1,440 分钟、顶部提醒开启。字段有后端取值范围校验，运行时从数据库读取。内部定时任务复用当前应用与数据库，无新增中间件。
